# 订阅组

订阅组从原生 sing-box JSON 文档下载节点，保留内部链式代理、组及 DNS 配置。刷新时一起校验、初始化和发布这些对象，无需重启内核。

## 配置示例

```json
{
  "http_clients": [
    { "tag": "download", "detour": "proxy" }
  ],
  "outbounds": [
    {
      "type": "subscription",
      "tag": "subscription-a",
      "url": "https://example.com/subscription.json",
      "http_client": "download",
      "bootstrap_http_client": {},
      "cache_path": "subscription-a.cache",
      "update_interval": "24h",
      "download_timeout": "30s",
      "max_download_size": 16777216,
      "max_cache_size": 67108864,
      "drain_timeout": "0s",
      "mode": "selector"
    },
    { "type": "selector", "tag": "proxy", "outbounds": ["subscription-a"] }
  ],
  "route": { "final": "proxy" }
}
```

`url` 必须是 HTTP 或 HTTPS URL。`http_client` 支持共享 HTTP 客户端标签或内联配置，继承其 TLS、请求头和拨号选项。省略时使用主配置默认 HTTP 客户端；显式 `{}` 表示直连并使用主配置的 DNS。

正常下载失败后，如果配置了 `bootstrap_http_client`，会使用它重试。不会自动回退直连。引导客户端的代理和 DNS 必须能独立工作，不能依赖尚未加载的订阅。

`cache_path` 保存最后一份成功应用的完整订阅、ETag、导入 selector 的选择、嵌套订阅和已下载的远程规则集。子订阅和规则集更新后也会更新父缓存，因此不必为每个子订阅单独设置路径。只提供父缓存即可离线恢复整个已提交的资源树。启动先恢复所有缓存，再下载缺少缓存的订阅；支持先加载一个订阅，再通过它引导另一个订阅。下载依赖形成环且没有缓存或独立引导路径时，启动返回明确错误。缓存与 URL 绑定，使用临时文件加重命名写入；目录权限为 0700，文件权限为 0600。

`update_interval` 默认 24 小时，过期缓存会在启动后刷新。`download_timeout` 默认每次下载尝试 30 秒，也用于组健康检查超时。`max_download_size` 默认 16 MiB，最大 1 GiB，限制解码后的响应体。下载、解析、依赖检查或初始化失败时，继续使用旧版本；下一次定时或手动刷新会重试。

引导期间主配置中直接定义的 DNS 规则已经生效，远程规则集会在订阅加载后下载，因此引导解析不能依赖尚未加载的远程规则集。必要时，在引导 HTTP 客户端中显式指定 `domain_resolver`。导入成员支持 TCP 和 UDP。

`drain_timeout` 默认 `0s`，旧连接关闭后才回收旧版本。设置正数可以限制旧版本保留时间；超时会关闭剩余连接。关闭内核会取消在途任务、强制关闭所有版本并等待资源回收。刷新期间的新连接使用新版本，已有 TCP/UDP 连接及下载连接继续持有原来的版本。旧资源树中的嵌套订阅会停止自动更新；回收工作异步执行，关闭内核时等待其完成。TCP 半关闭和延迟握手能力会透传。

`empty_fallback` 支持[空组备用节点](../shared/group-import.md#empty_fallback)，引用当前配置文档中声明的节点或组；仅在已加载文档的成员与过滤后导入成员合并为空时插入。

`import` 支持带过滤条件的[组导入](../shared/group-import.md)。导入成员追加到自身文档的成员之后，并跟随来源更新，支持多级导入。`outbounds` 仅筛选下载文档；`default` 也可使用导入成员的完整标签。

## 节点选择与测速

可选字段：

| 字段 | 行为 |
| --- | --- |
| `outbounds` | 以原始标签指定可选节点，省略则展示全部出站和端点；未展示的依赖仍会保留 |
| `default` | 自身节点的原始标签或导入成员的完整标签；刷新后优先保留仍存在的当前选择，否则回退到默认或首个节点 |
| `mode` | `selector`（默认）或 `urltest`，两者都支持手动选择 |
| `test_url` | 测速 URL，省略使用标准 URLTest 默认值 |
| `test_interval` | 自动测速间隔，默认 3 分钟 |
| `tolerance` | 自动切换容差，单位毫秒，默认 50 |

`urltest` 在成功刷新后立即重新测速，并清除旧版本的延迟记录；周期测速仍按 `test_interval` 执行。它按 TCP 测速结果为各网络选择可用成员，支持 UDP 的成员也使用该结果；它不代表 UDP 可达性探测。旧版本的测速结果不会改变新版本的选择。

## 订阅内容

```json
{
  "dns": {
    "servers": [
      { "type": "udp", "tag": "resolver", "server": "1.1.1.1" }
    ]
  },
  "outbounds": [
    {
      "type": "socks",
      "tag": "relay",
      "server": "relay.example.com",
      "server_port": 1080,
      "domain_resolver": "resolver"
    },
    {
      "type": "socks",
      "tag": "exit",
      "server": "exit.example.com",
      "server_port": 1080,
      "detour": "relay"
    }
  ]
}
```

出站与端点共用标签空间，DNS、HTTP 客户端、规则集、网络命名空间和证书提供者分别具有自己的标签空间。各命名空间内标签必须唯一。出站、端点、DNS 服务器和证书提供者省略标签时，与原生配置一样使用各自数组下标（从 `0` 开始）；建议显式命名，避免调整顺序改变引用。HTTP 客户端、规则集和命名空间仍需显式标签。引用优先匹配来源文档的资源，并自动改写为隔离后的标签。selector、urltest 的 `outbounds` 必须引用同一文档声明的资源，跨订阅获取组成员应使用 `import`；其余资源引用未在文档中定义时，可以指向主配置或父订阅已有的资源。不存在的引用会报错。

内部节点 detour、组成员、解析器链和 DNS detour 都参与依赖校验；任何可能的组选择形成环都会被拒绝，而不仅检查当前选择。使用 IP 对端的隧道不会被错误地视为依赖 DNS。提交前还会合并主配置和其他已加载订阅的依赖图，并串行校验与提交，防止并发更新共同形成环。首次加载允许暂存指向其他尚未加载订阅的节点引用，在开放服务前对完整资源树严格校验，因此节点级无环的相互引用可正常启动；真实缺失引用和环路仍会报错。热更新提交前会再次校验完整候选资源树。拨号路径另有按节点记录的循环保护；无环地经过同一订阅的不同成员是允许的，并保留该次拨号已持有的版本、组选择和网络能力判断，避免刷新过程中混用新旧节点。

DNS 使用订阅私有作用域，保留服务器选项、解析器链、规则、默认服务器与客户端选项。引用其他作用域的 DNS 服务器时复用该服务器；来源定义不会覆盖主配置。导入节点保留 `route.default_domain_resolver`；没有显式 resolver 时使用订阅的 DNS 规则或默认服务器；订阅未提供 DNS 时继承父作用域的解析行为。FakeIP 用于拦截应用流量，不适合作为代理服务器地址的解析器。

支持以下原生资源：

* `outbounds` 和 `endpoints`，包括 selector、urltest 及嵌套 subscription；协议可用性与当前二进制的构建标签一致。
* `dns` 和 `route.rule_set`，包括内联、本地和远程规则集；规则集 URL/路径的 `{tag}` 仍按来源标签展开。
* `http_clients`、`route.default_http_client` 和 `route.final`，用于来源资源的默认下载路径。
* `certificate`、`certificate_providers` 和 `network_namespaces`，以及它们对已有外部资源的引用。
* `route` 中的默认解析器、接口、路由标记、网络选择和回退拨号选项。

这是节点与其依赖的导入，不安装来源文档的全局入站、流量路由规则或服务，也不更改主配置的系统路由与接口监控策略。文件路径按 sing-box 的配置基础目录解析。端点本身的监听端口、系统接口和状态目录仍遵循该协议的原生约束；新旧版本无法同时占用独占资源时，刷新会失败并保留旧版本。

嵌套订阅使用相同的下载、引导、缓存和回滚机制。祖先链中重复的订阅 URL 会被拒绝，避免递归导入。父订阅刷新时建立完整的新资源树，子订阅也可以单独刷新。在来源文档内部可用 `subscription/child/exit` 引用子订阅的成员，导入时会递归改写命名空间。

Clash API、原生 API 和客户端界面优先使用订阅中的原始节点名或组名，中文、空格及特殊字符不会在名称中进行 URL 编码。与主配置标签或其他订阅成员名称冲突时，依次尝试 `原名-1`、`原名-2`，跳过已占用名称。主配置标签优先保留；同一批新增成员的原名优先于自动生成的后缀。

名称绑定内部节点身份。刷新、改动节点参数或删除重加不会改变已分配的名称，其他节点也不会接管暂时被删除节点的名称。名称分配随订阅缓存保存，缓存恢复时可保留后缀；未配置缓存时，新进程根据当时的配置、加载顺序和成员重新分配。父订阅更新失败不会占用候选子订阅的名称。同一来源文档内重复的原始标签仍然属于无效原生配置。

API 的组列表、当前选择、测速结果、provider 列表和连接链使用同一套名称，选择和测速请求使用接口返回的名称。HTTP URL 路径的传输编码仍由客户端执行一次，不属于显示名称。配置引用、过滤和链式代理使用下面的稳定身份，显示名称不会改变这些依赖。

导入成员的内部稳定标识为 `subscription/<转义后的订阅组标签>/<转义后的原节点标签>`，转义使用 URL 路径片段转义。例如组 `sub` 的节点 `exit` 是 `subscription/sub/exit`；子组 `child` 的 `exit` 是 `subscription/subscription%2Fsub%2Fchild/exit`。selector、urltest 的 `outbounds` 不能直接填写来自其他订阅文档的这些成员标签；应使用 `import` 获取成员，或在 `outbounds` 中引用当前文档声明的订阅组本身。路由（包括 `route.final`）仍可以引用稳定成员标签，引用已删除的成员会报错；引用订阅组标签则由组负责节点变更后的回退。

Clash API 和 daemon 可以查询、选择导入的内部组。仍然存在的内部 selector 选择会在刷新和缓存恢复后保留。Clash provider 接口同时支持根订阅和嵌套订阅；请求路径中的标签还需按 HTTP 路径参数再次编码。

`max_cache_size` 限制整个缓存文件大小，默认取 64 MiB 与 `max_download_size` 两倍中的较大值，最大 2 GiB。超过限制会记录缓存写入错误，已成功运行的新版本保持有效，磁盘上保留上一份缓存。`max_download_size` 仅限制单个订阅文档；两者均不限制原生规则集自身的下载。

仅接受原生 sing-box JSON（包括配置注释）；不提供 Clash YAML、URI 或 Base64 订阅转换。

## 更新语义与限制

* 同名节点配置变更后，已保留的成员句柄会用于新版本拨号；删除节点后，该句柄报不可用，重新加入同名节点后恢复可用。
* 明确提供 `{"outbounds":[]}` 或 `{"endpoints":[]}` 可以清空订阅。这会清空自身文档的成员，`import` 的成员仍然保留；最终没有普通成员时，使用 `empty_fallback`（若已配置），否则拨号报错；`ready` 表示文档已加载，不代表已有可用节点。缺少这两个字段的空文档仍视为错误。
* selector、urltest 的 `outbounds` 在配置检查或订阅文档加载时按同一文档的声明静态校验，不能引用其他订阅组内部成员。订阅文档删除仍被本地组引用的节点时，会拒绝本次更新并保留旧版本。使用 `import` 可以动态跟随其他组的成员增删，也可以通过 `outbounds` 引用当前文档声明的订阅组本身。订阅自身的 `outbounds` 白名单仅选择下载文档声明的成员，缺少要求的节点时同样拒绝更新。
* 环检测是保守检查：包含所有候选组成员、DNS 规则目标和已知的隐式解析依赖，不尝试证明条件规则互斥。因此，某些按域名条件分流、实际不会触发循环的配置也可能被拒绝；为代理服务器显式指定独立的 `domain_resolver` 可以表达清晰的引导路径。
* 当前成员封装支持 TCP/UDP 拨号以及 `preferred_by` 查询。原生端点的 ICMP/Flow 转发接口没有透传，因此导入端点不等同于静态配置端点的全部能力。
* 父版本被替换后，旧子订阅不能再提交更新；旧版本的订阅刷新、组成员监听和测速会停止。关闭订阅时也会等待已接受的手动测速退出并释放版本引用。旧连接结束后，关闭的版本会及时从回收列表移除，无需等待下一次刷新。
* `drain_timeout: 0` 不承诺旧资源的回收时间上限；一直未关闭的连接会一直保留对应版本。正数会在超时后关闭剩余连接。

## 手动操作

使用已有 Clash API 认证和接口：

* `GET /providers/proxies`：查询全部订阅。
* `GET /providers/proxies/{name}`：查询就绪状态、版本号、更新时间、错误及成员。
* `PUT /providers/proxies/{name}`：手动刷新并等待完成。
* `GET /providers/proxies/{name}/healthcheck`：执行健康检查。
* `PUT /proxies/{name}`，请求体 `{"name":"香港节点-1"}`（使用 API 返回的成员名称）：选择节点。

同一订阅的手动和定时刷新串行执行。HTTP 下载使用独立连接池，结束时释放自己的连接，不重置其他共享客户端。
