`smart-urltest` 同时使用 HTTP URL 测速和实际 UDP DNS 查询对实时组成员排序，并按目标缓存成功使用的出口。支持现有 `urltest` 的动态导入与订阅隔离。

### 结构

```json
{
  "type": "smart-urltest",
  "tag": "smart",
  "outbounds": ["proxy-a", "proxy-b"],
  "import": [],
  "empty_fallback": "",
  "url": "https://www.gstatic.com/generate_204",
  "udp_test": {
    "server": "8.8.8.8",
    "server_port": 53,
    "domain": "example.com",
    "timeout": "5s"
  },
  "interval": "5m",
  "tolerance": 50,
  "cache_ttl": "5m",
  "cache_capacity": 10000,
  "dial_timeout": "5s",
  "failure_window": "1m",
  "failure_threshold": 5,
  "udp_response_timeout": "5s",
  "udp_failure_window": "1m",
  "udp_min_sessions": 10,
  "udp_failure_ratio": 0.8,
  "min_test_interval": "30s",
  "test_concurrency": 10,
  "max_concurrent_dials": 64
```

### 成员与选择

`outbounds`、`import`、`empty_fallback` 至少配置一项。静态 `outbounds` 和 `empty_fallback` 必须引用同一配置文档中的声明。订阅内部成员使用 [组导入](../shared/group-import.md)，支持过滤、多级导入，保留节点的私有 DNS、链式拨号和订阅版本租约。

`empty_fallback` 仅在有效成员为空时插入，正常成员恢复后移除；组非空时不会因为拨号失败而插入。没有回落成员的空组仍可完成启动，拨号时返回不可用错误。

TCP 流量优先使用 TCP 与 UDP 都测试成功的节点，其次是只有 TCP 成功的节点；TCP 测试失败的节点不参与 TCP 选择。相同健康等级先比较 TCP 延迟，TCP 延迟相同时比较 UDP 延迟。只有当前节点 UDP 也成功时，才应用 `tolerance` 毫秒的 TCP 容忍区间；UDP 失败或尚未测通时不会因容忍区间保留较差的节点。省略 `tolerance` 使用 50 ms，显式 0 表示禁用容忍区间。没有双协议成功的节点时，仍可选择 TCP 正常的节点；不会在同样失败的节点之间无意义地轮换。

尚未测过的成员保留启动尝试机会，优先级低于已测通 TCP 的成员。全部已测成员的 TCP 都失败时，TCP 暂时不可用；定时测试仍检查全部成员，恢复后重新纳入。候选还必须声明支持请求的网络。UDP 流量按照实际 UDP 选中的最终节点评估：已测通的节点优先于未测试节点，失败节点排在最后；HTTP 测试失败不会排除已测通 UDP 的节点。嵌套组的 TCP 与 UDP 选择分别递归解析，不能互相借用健康结果。

每次连接：

1. 优先选择目标的有效缓存出口，否则选择当前最优节点。缓存不能绕过 TCP 失败、UDP 降级或健康等级提升带来的切换。
2. 首次尝试受 `dial_timeout` 限制；失败或超时后，尝试排名靠前的最多 **3 个**其他候选，排除首次尝试的节点。同一健康等级内并发拨号，较高等级全部失败后再尝试下一等级。
3. 返回并缓存首个成功连接，取消其余尝试并关闭其连接，包括取消后才返回的成功连接。每个备选有独立的 `dial_timeout`。

排名变化不会断开已建立的连接。应用数据发送后不再重拨或重放。采用延迟握手的协议可能在首次写入时才报告错误：此时删除对应缓存并记录健康失败，但不会将应用数据重新发送给其他服务器。

### 目标缓存

`cache_ttl` 是固定的最长保留时间，默认 5 分钟。读取或重复成功不会延长它。优先使用嗅探域名，否则使用实际拨号的域名或 IP；域名忽略大小写，TCP 与 UDP 分开缓存，同一目标不同端口共享该网络的绑定。智能组被用作链式拨号器时，以实际代理服务器为目标，避免混用原始应用的域名。

`cache_capacity` 默认 10000 条，满时淘汰最早的记录。缓存只保存在内存中。成员版本或接口变化会清理缓存；即使节点标签未变，订阅刷新也可能改变其地址或拨号链，因此旧版本的在途拨号和测速不得回写。API 清理同样阻止清理前已经开始的拨号重新填入旧绑定；旧连接失败也不会误删后来重新创建的同名绑定。

### 测速与健康触发

| 字段 | 默认值 | 含义 |
| --- | --- | --- |
| `url` | `https://www.gstatic.com/generate_204` | 完整 HTTP(S) 测速地址。 |
| `udp_test.server` | `8.8.8.8` | UDP DNS 服务器 IP 或域名；地址中不包含端口。 |
| `udp_test.server_port` | `53` | UDP DNS 端口。 |
| `udp_test.domain` | `example.com` | 查询 A 记录的域名。 |
| `udp_test.timeout` | `5s` | 包括建立代理连接和等待 DNS 回复的超时，范围 1ms–1m。 |
| `interval` | `5m` | 定时测速，包括空闲期间。启动、成员或接口变化也会请求测速。 |
| `failure_window` | `1m` | 业务拨号失败的滑动统计窗口。 |
| `failure_threshold` | `5` | 次数**超过**该值时请求测速并重置窗口，默认第 6 次触发；失败的备选拨号也计数。 |
| `udp_response_timeout` | `5s` | UDP 会话发包后等待回复的观察时间。 |
| `udp_failure_window` | `1m` | 已完成 UDP 观察结果的滑动统计窗口。 |
| `udp_min_sessions` | `10` | 判断失败比例前至少需要的会话观察数。 |
| `udp_failure_ratio` | `0.8` | 无回包比例达到该值时请求测速，并重置统计窗口。 |
| `min_test_interval` | `30s` | 自动测速两次开始之间的最短间隔；面板 TCP 测速不受此冷却时间影响。 |
| `test_concurrency` | `10` | 每组同时测试的节点数量；每个支持 TCP 的节点先执行最多 15 秒的 HTTP 测试；每个支持 UDP 的节点再按 `udp_test.timeout` 执行独立 UDP 测试，不以 HTTP 成功为前提。 |
| `max_concurrent_dials` | `64` | 每组实际运行的业务/备选拨号数量上限，等待名额也计入此次拨号超时。 |

自动触发会合并并限流。面板 TCP 测速独立执行，不等待自动测速的 UDP 阶段或冷却时间。测速流量带有贯穿嵌套组的标记，不计入业务失败统计，也不会建立或修改目标缓存。主动取消和本地并发名额不足不计为节点故障。

UDP 观察覆盖普通 socket 方法与缓冲区读写方法。没有发包的空闲会话不计数；每个会话每个窗口最多贡献一个结果，长连接在后续窗口重新采样。无回复的会话被关闭后仍会完成其观察，避免客户端超时关闭掩盖故障。每组最多保留 10000 个待观察会话，达到上限时暂时跳过新增观察。使用一个定时器及 64 个时间桶限制长期内存占用，窗口精度约为 `udp_failure_window / 64`，最小 1 ms。

HTTP 测速成功不代表 UDP 可达，因此每轮会对候选范围内全部声明支持 UDP 的最终节点执行 UDP DNS 查询，包括嵌套组中未选中的成员、HTTP 测试失败的成员和仅支持 UDP 的成员。同一轮按最终节点去重，使用发起测试组的 URL 和 UDP 参数；只存储最终节点的结果。省略 `udp_test` 时仍启用默认探测。每次直接通过节点交换新 DNS 报文，不读取内核 DNS 缓存，也不回退到 TCP。成功必须收到 ID、问题及类型匹配、未截断、NOERROR 且包含 A 答案的响应；错误、超时和空答案均判失败。UDP 业务统计会触发新的双协议测试，但不重发业务数据报。不响应取消的底层拨号会一直占用并发名额直到真正返回，避免超时重试不断积累工作协程。

### API 与代理链

Clash 兼容 API：

- `GET /group/{name}/delay?timeout=5000`：按配置的 URL 测试 TCP 并更新排名；显式传入同一 `url` 时行为相同。请求使用独立超时，不等待自动 UDP 探测。
- 使用不同的 `url` 时执行现有面板独立探测，例如 IPv6 测试，不覆盖智能组的主排名。
- `DELETE /group/{name}/cache`：清理指定智能组全部目标缓存，返回 204；非智能组返回 400，不存在的名称返回 404。
- `DELETE /connections/{id}`：清理该连接实际经过的各智能组所使用的目标绑定，再关闭连接。拨号尚未结束时清理，也会使稍后生成的绑定失效。
- `DELETE /connections`：清理所有已注册智能组的缓存，包括没有活跃连接的组，然后关闭连接。

名称沿用面板公开名称映射与 URL 路径转义。原生 daemon 的单连接/全部连接关闭 API 使用相同清理逻辑。普通连接关闭不会清理缓存。

面板中该组显示为 `SmartURLTest`，`now` 表示默认最优节点。连接的 `chains` 记录实际获胜路线，包括缓存命中、备选节点、嵌套选择与实际拨号时经过的 detour，不用当前默认值替代真实出口；失败或落败的尝试不会发布代理链。测速会在开始时递归固定当前选中的最终节点，包括嵌套智能组；不会借用业务流量的备选拨号来掩盖被测节点失败。业务缓存仍保留目标亲和性，但不能覆盖上述健康优先级。

复用连接保留所属传输会话的实际路线，覆盖通用 multiplex、AnyTLS、Snell、SSH、HTTP/2、gRPC（含完整实现）、V2Ray QUIC、Hysteria、Hysteria2 和 TUIC。后续默认节点变化不会改写已有会话的路线；Hysteria 端口跳跃替换底层连接时，路线跟随当前传输。为代理服务器查询 DNS 时产生的辅助拨号不计入应用连接的代理链。

测速记录仅以「最终节点 + 完整测速 URL」为键保存在内存中，不保存组的延迟副本。自动测速、面板测速及 IPv6 测速使用同一存储规则；每个节点最多保留 64 个 URL 的最新结果。失败仅影响对应 URL，较早启动但较晚完成的探测不能覆盖较新的结果。

例如 A → B → C → 节点 X：查询 A 默认读取 X 在 A 的 URL 下的结果；查询 B 读取 X 在 B 的 URL 下的结果。B 改选节点 Y 后，A 立即读取 Y 在 A 的 URL 下的结果；若尚未测过该组合则无结果，不借用 X 或其他 URL 的延迟。组的排名也按当前最终节点和本组 URL 计算。

`GET /proxies`、`GET /proxies/{name}`、`GET /group`、`GET /group/{name}` 以及代理提供商查询支持 `url` 参数，返回该 URL 的 `history`；不指定时组使用自身配置 URL，普通节点使用默认 URL。`extra` 提供按 URL 区分的历史，`testUrl` 表示配置的测速 URL，记录的 `outbound` 是被测最终节点的公开名称。代理提供商健康检查同样接受 `url`、`timeout`。

面板独立探测按请求的 `timeout` 限制等待时间；显式配置超过 15 秒时，HTTP 阶段不会再被静默截短为 15 秒。内核自动探测仍使用 15 秒的单节点期限。取消请求不改写已有测速记录；超时后才结束的拨号会自行释放连接，迟到结果不会重新发布。独立面板探测的后台拨号在进程内最多同时运行 256 个，等待本地并发名额超时不会被记为节点故障。

### UDP 实测接口

`GET /proxies/{name}/udp-delay?server=8.8.8.8&port=53&domain=example.com&timeout=5000` 执行真实的 UDP DNS 查询；超时参数单位为毫秒。省略参数时使用被测智能组的 `udp_test`，普通节点使用默认值。测试会递归固定当前 TCP 选择对应的最终节点，再测试该节点的 UDP，不借用组内其他节点的成功结果。返回 `alive`、`delay`、`time`、`outbound` 和探测参数；已执行但失败的探测返回 HTTP 200 与 `alive: false`。参数错误为 400，测试期间成员版本变化为 409，无法开始测试为 503。

`GET /version` 宣告 `udp-probe-v1`；代理信息的 `udpTest` 给出本组测试参数，`udpHistory` 给出当前最终节点的实测记录。UDP 记录按节点、服务器、端口、域名和超时隔离，每节点最多保留 64 组。订阅内部组与面板共用当前版本节点的记录；订阅更新切换到新版本记录，旧请求不能覆盖新版本，取消请求不抹除记录。传统 `udp` 字段仍只表示协议声明的能力；面板保持原有节点卡片布局，延迟始终显示 TCP 结果。原有 UDP 标签仅在实测成功时显示，未测试或失败时隐藏。单节点、组、提供商测速同时触发后台 UDP 实测，TCP 结果和加载状态不等待 UDP 完成。
